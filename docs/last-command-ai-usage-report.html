AI 도구와 역할

본 프로젝트는 OpenAI Codex를 개발 보조 에이전트로 사용했습니다. 사용자가 목표와 제약, 수정 우선순위를 결정하고 AI가 저장소 분석·코드 작성·리팩터링·검증 스크립트 작성·문서화를 수행한 뒤, 실제 실행 결과를 기준으로 반복 수정했습니다.

H↔AI

Human-in-the-loop 공동 개발

AI의 출력은 바로 제출 결과로 간주하지 않았습니다. 기능 단위로 브라우저 실행, 콘솔 오류, 저장 상태와 버튼 동작을 확인한 후 사용자가 커밋·푸시를 명시적으로 승인했습니다.

PRIMARY AI TOOL
OpenAI Codex

GPT-5 기반 개발 에이전트. 자연어 요구를 파일 단위 구현 계획과 코드 패치로 변환하고, 기존 구조를 읽어 변경 범위를 제한했습니다.

브라우저 테스트
ENGINEERING TOOL
Git · Shell

검색, 문법 검사, 변경 비교, 커밋 이력 기록에 사용했습니다. 각 기능은 독립 커밋으로 남겨 AI 활용 결과를 추적할 수 있습니다.

실패를 숨기지 않는 검증

테스트 코드도 처음부터 항상 정답은 아니었습니다. 결과 UI가 Phaser Container 내부로 이동해 일반 display list 검색이 실패했을 때, 실제 장면 구조를 조사하고 테스트가 Container 자식을 검사하도록 수정한 뒤 다시 통과시켰습니다.

남아 있는 한계

브라우저 자동 테스트 스크립트는 검증 중 임시로 실행했으며 저장소에는 테스트 프레임워크 형태로 유지하지 않았습니다. 향후 정식 회귀 테스트를 저장소에 포함하면 재현성이 더 높아집니다.

사용자 승인 지점

기능 구현 후 변경 내용과 검증 결과를 사용자에게 보고했으며, 사용자가 “커밋 푸시”를 요청한 단계에서만 Git 커밋과 원격 저장소 반영을 수행했습니다. AI가 임의로 배포 범위를 확장하지 않도록 승인 경계를 유지했습니다.

위험과 대응

코드 오류·환각문법 검사만으로 끝내지 않고 실제 Chrome에서 장면과 저장값을 확인했습니다.
요구 범위 이탈기존 구조와 Git 상태를 먼저 읽고, 사용자 요청에 해당하는 파일만 단계적으로 수정했습니다.
저작권·모방 위험특정 상용 게임의 캐릭터, 지명, 스토리, UI, 그래픽, 음악을 사용하지 않는 조건을 기준 프롬프트에 명시했습니다.
개인정보·네트워크게임은 백엔드가 없으며 진행 데이터는 사용자의 브라우저 localStorage에만 저장됩니다.
